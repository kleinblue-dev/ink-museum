# 墨馆 · 博物馆水墨软件的 REA 拆解

> 方法：REA（Reverse Engineering Analysis）= **R**econ 侦察 → **E**xtract 提取 → **A**bstract 抽象（沿用 `mojian/docs/01-REA-底层框架.md` 的三步法与三条纪律：事实与推断分离 / 不发写请求 / 可复现）。
> 对象：博物馆/馆藏向的水墨书画浏览软件。目标不是复制任何一家的界面，而是**抽出可迁移的展陈语法**，再落到「墨馆」这一间小馆的实现里。
> 证据等级：标注【实测】= 本次抓取页面可直接核验；【推断】= 基于公开展陈通行做法，未逐帧核验。

## 1. Recon（只读侦察）

| # | 对象 | 线上地址 | 实测观察 | 推断 |
|---|---|---|---|---|
| R1 | 故宫名画记 | <https://minghuaji.dpm.org.cn/> | HTTP 200；首页直接以名作立门面（顾恺之《洛神赋图卷》、张择端《清明上河图卷》、王希孟《千里江山图》）；按「作品 / 流派 / 作家 / 时代卷轴」组织；有「典则：唐宋书画展」分期专题、作品综述、学术资讯、版权/影像授权入口 | 博物馆水墨软件的第一屏不是功能列表，而是**一件镇馆之作为入口**；知识结构（作者/流派/时代）藏二级，不占首屏 |
| R2 | 中华珍宝馆 | <https://www.ltfc.net/> | HTTP 200；Next.js 站点；导航为「绘画馆 / 书法馆 / 所有分馆 / 推荐画单 / 新发图 / 展览 / 拾英」；首页有「本周看图 0.0 小时」「画谱搜索」「书法集字」「珍小宝 AI」「精简版」 | 高清书画浏览器的核心动作是**看**：以「画单（收藏夹/主题单）」和「看画时长」把浏览变成一种可持续的观看习惯；「画谱」是给普通人的专业入口 |
| R3 | 故宫数字文物库 | <https://digicol.dpm.org.cn/> | HTTP 200；「藏品总目」+ 生肖/节令专题（百骏迎春、辰龙献瑞…）；筛选维度为 Category / Period / Color；结果为异步加载 | 馆藏浏览的标准骨架 = **专题策展 + 多面筛选 + 无限流**；专题比筛选更先出现 |
| R4 | 故宫博物院官网「数字」板块 | <https://www.dpm.org.cn/shuzi/> | 抓取返回空壳（前端渲染/反爬）；不计入实测结论 | 官网常把数字产品（名画记/文物库/全景故宫）作为二级入口，不做大而全聚合 |

**三条纪律落地**：
1. 只 GET 公开页面，不发任何写请求、不绕登录、不抓图片资源本体（背景图一律改用 Wikimedia Commons 的公有领域版本）。
2. 以上每条结论都对应页面上可见的导航文字/专题名/功能名；页面渲染时序与内部实现不臆测。
3. 本文件的「借用」只借**结构关系**（谁先出现、谁承载什么、什么被隐藏），不借品牌、配色、文案、图片。

## 2. Extract（可迁移的展陈语法）

把四家放在一起横向看，博物馆水墨软件真正稳定的东西只有 6 条：

| # | 语法 | 证据 | 对「墨馆」的翻译 |
|---|---|---|---|
| E1 | **一画入口** | R1 首页 = 三件名作 + 分期专题 | 入馆页只给一幅《富春山居图》和一扇门，不铺功能宫格 |
| E2 | **全幅优先、UI 退后** | R1/R2 均以作品画面为主体，导航/元数据在边缘 | 画作全屏、工具条沉底、文字做成「展签」尺寸（≤2 行、≤90 字/屏） |
| E3 | **策展动线而非自由探索** | R1「典则」分期展；R3 专题先于筛选 | 七步动线固定（来时→择境→一句→落墨→此刻→收卷），不给无限分叉 |
| E4 | **展签/题跋/印章是信息层** | R1 有作品综述/作者/朝代；R2 有画单与画谱 | 每个展厅只留：2 字厅名 + 一幅画 + 一行诗；落款用朱砂印，不用卡片 UI |
| E5 | **观看是可积累的行为** | R2「本周看图时长」「推荐画单」 | 收卷生成「自己的画卷」+ 馆藏墙留痕；不做排行榜/积分 |
| E6 | **出处与授权是门面的一部分** | R1 明确「影像授权」；R3 版权/隐私入口 | 关于页写清公有领域出处、隐私边界、非医疗建议；页脚常驻一句 |

**被我们主动拒绝的**（避免把小馆做成大平台）：
- ❌ 高清瓦片缩放、多图层题跋标注（工程量吃掉全部预算，手机端并不好用）
- ❌ 会员/登录/下载付费（与"一段与自己的相处"冲突）
- ❌ AI 助手问答（引导语必须离线、可控、不被模型随机性破坏）
- ❌ 无限浏览与信息流（会破坏 8 分钟仪式感）

## 3. Abstract（与题材无关的六层框架）

```
L1 展厅层   一画入口 / 全幅背景 / 展签级文字 / 暗场灯光      （换皮不动骨）
L2 动线层   线性 7 步 + 单向推进 + 浮层（馆藏/关于）        （可换任意仪式）
L3 干预层   一句引导 → 一个动作（落墨）→ 一句承接            （换文化母题即换内容）
L4 创作层   透明画布：自由笔 + 芥子园墨块 + 撤销/收笔        （媒介无关，可换）
L5 记录层   匿名 session + 前后自评 + 画卷图 + 馆藏墙        （可换存储/可关）
L6 治理层   公有领域出处 / 隐私最小化 / 非医疗免责 / 无外链  （不换，是底线）
```

层间不变式（实现时守住）：
- **画面先于控件**：任何一步，用户先看到画，再看到可点的东西。
- **文字有预算**：每屏可见中文 ≤90 字；关于页是唯一的文本仓库。
- **动线不鼓励退**：除返回上一步外不回退到 create 之后的状态；reveal 之后锁定。
- **data 最小化**：服务端只收匿名 id + 7 点自评 + 画卷；不收自由文本（同时消灭 XSS/UGC 审核负担）。
- **媒介不宣称疗效**：文案只说"相处/停一会儿"，不出现治疗/疗愈/改善疾病。
- **资产有出处**：每张背景可追溯到 Commons 文件页；运行时零外链。

## 4. 落点：借鉴 → 墨馆的具体决定

| 决定 | 来自 | 实现位置 |
|---|---|---|
| 入馆 = 一画 + 一门 + 一句 | E1 | `js/journey.js` enter 步 / `content.entry` |
| 四展厅 = 四幅宋元名作 + 2 字厅名 + 一行诗 | E2/E4 | `content.scenes` + `assets/bg/*` |
| 择境用画卡而非列表；动线固定 7 步 | E3 | `js/state.js` 迁移守卫 |
| 落墨 = 自由笔 + 芥子园墨块；工具条沉底 | E4/L4 | `js/ink/engine.js` + 前台工具条 |
| 收卷 = 画卷 + 朱砂印 + 展签 + 日期；存入馆藏墙 | E5 | `js/export.js` + `server/routes` |
| 前后自评只用三个小墨点，不显示分数 | E2/E5 | `reveal` 步 + `content.feedback` |
| 关于页 = 出处/隐私/免责/前身 | E6 | `#about` 浮层 + `content.about` |
| 一套内容源同时驱动前台与后端 | 工程约束 | `content/content.js`（前端 import / 后端 import） |

---

## 5. 结论（一句话）

**博物馆水墨软件值得拿的不是它的高清浏览器，而是「一画入口—全幅优先—策展动线—展签文字—留痕可带走—出处可见」这六条关系。** 「墨馆」把它们压缩到 5–8 分钟、4 幅画、1 枝笔的可完成尺度里，并用前后端分离保证以后换画、换文案、换存储不动骨架。
